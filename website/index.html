Core Gameplay

Master the mechanics of Paint Battle

Marble Mechanic

Marbles fire automatically from your cannon on a fixed timer that accelerates as the match progresses. In Standard mode, the timer starts at 3000ms and shortens over time. Quick mode starts faster for shorter matches.

Marbles drop through a branching track where they can: split into multiple marbles, combine with others, or determine which unit spawns.

Factions

Before each match, select your faction. Each has: exclusive marble color, signature mechanic/buff, faction level, and exclusive units/cards.

Weapons & Combat

Units are split into two weapon classes:

🖌️

Paintbrush

Melee units that engage enemies directly.

🎯

Paintball Gun

Ranged units firing paint charges.

Map & Tiles

The battlefield is a square grid. Walls exist on boundary edges with their own HP pool. Intact walls block movement, destroyed walls become passable, and claimed edges re-lock against the opposing team.

How It Works

1

Match Ends

Game Server flushes full match event log to database

2

Job Queued

If AI feedback enabled, job is queued to AI Coach Service

3

Analysis

Service reads match event log + player's unit/card tiers and faction data

4

LLM Prompt

Structured prompt sent to LLM requesting performance feedback

5

Report Stored

Response stored and surfaced on post-match screen + match history

System Architecture

Designed for performance and scalability

The system is split by responsibility to keep the real-time match path fast while supporting persistent, data-driven progression.

🎮

Game Server

  • Runs live match simulation
  • Marble resolution, auto-battle, wall/tile state
  • WebSocket communication with clients
  • Persists state changes to MySQL
🔐

Auth/API Server

  • Handles login and profile
  • Shop, chests, upgrades, loadouts
  • REST/HTTPS communication
  • Reads/writes MySQL directly
🎯

Matchmaking Service

  • Queues players for Ranked, Casual, or Private matches
  • Hands off ready matches to Game Server
🤖

AI Coach Service

  • Runs only after match ends
  • Reads logged match event data
  • Generates post-match feedback via LLM
  • Kept outside real-time path
🗃️

MySQL Database

  • Persistent store for players, factions, catalog data
  • Player-owned collections
  • Matches and economy
